## Fixed Issues

1. YonedaDistance label leakage

`oracle/yoneda_strategy.py` used a module-level cache built directly from `tier1.db`. That cache loaded all Drug->Disease labels and ignored the graph supplied by the benchmark fold. As a result, `remove_direct_labels` and LOOCV folds still exposed held-out labels to the Yoneda comparator set and fingerprints.

Fix: Yoneda now builds from the caller-visible category, excludes direct Drug->Disease labels from fingerprints, and derives known-treatment comparators only from visible fold labels.

2. Cross-type analogy in YonedaPattern

`YonedaPatternStrategy` could treat proteins/functions as analogs for drugs if they had similar outgoing relation names and connected to the disease.

Fix: comparators must have the same source object type.

3. BindingEvidence disease-agnostic votes

`BindingEvidenceStrategy` previously scored a drug's best target binding even when that target had no graph link to the queried disease.

Fix: binding evidence now requires an observed Drug->Protein->Disease path and reports disease-linked target support only.

4. Composition confidence mismatch

`CompositionStrategy` used `min(edge_confidences)` while the mathematical docs and core enriched-category code use multiplicative confidence.

Fix: composition now uses `drug_to_protein_conf * protein_to_disease_conf`.

5. Label-derived protein->disease bridges in strict validation

Some protein->disease edges were explicitly generated by projecting a drug's known indications through that drug's targets (for example provenance/metadata containing `via_drug` or `Drug-Target-Disease`). These edges can leak held-out indications through a different edge type.

Fix: `load_full_typed_view(..., remove_direct_labels=True)` and LOOCV fold loading now remove these explicit bridge edges.

6. Silent strategy failures during validation

The benchmark previously swallowed strategy exceptions and treated failures as abstentions.

Fix: benchmark evaluation now fails loudly on strategy errors. The UI still tolerates abstentions for demo usability.

## Evidence/Provenance Caveats

- The database has source/provenance strings on all 5,382 morphisms.
- There are 609 PMID identifiers in provenance/metadata strings.
- This is not equivalent to saying every edge has edge-specific citation validation.
- Quantitative NLP extraction metadata needs a separate attribution audit because some values appear attached by shared PMID rather than by endpoint/relation-specific extraction.
- Evidence tiers should not be read as regulatory or experimental certainty until the extraction and tiering pipeline is repaired and rerun.

## Retired Or Superseded Claims

The following claims should not be presented as current:

- `0.9689 AUROC / 0.661 AUPRC`
- `0.9562 AUROC` as the current strict result; it was an intermediate post-leakage result superseded by the current strict run
- LOOCV, Hetionet, temporal, and disease-holdout values from before the corrected loader reruns
- "581 unique validated PMIDs" and "100% validated provenance"
- shortest-path baseline `0.931` for the current strict graph

## Validation Work Status

1. LOOCV has been rerun under the corrected loader: AUROC 0.975916, AUPRC 0.553703.
2. External, temporal, and disease-holdout scripts are executable and rerun; Hetionet external precision-at-top remains weak.
3. A read-only citation-attribution audit is still required for each edge: endpoint mentions, relation support, quantitative value support, and abstract/full-text provenance.
4. Evidence tiers must continue to separate source type from validation status. Computational ESM2 or unverified NLP extractions must not be described as direct measurement.
5. Ranking scores must stay separate from strategy signal scores. Current scores are prioritization/ranking scores, not clinical probabilities.
